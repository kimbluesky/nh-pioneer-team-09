# [제보] NH FUTURES API: 해외 주문 취소 시 다음 페이지에 남은 원주문을 확인하지 않고 취소 완료로 표시합니다

팀: team-09  
환경: Windows / Python 3.12.10 / Node.js v24.22.1, 2026-11-16 (KST)  
대상: 공개 저장소 NH FUTURES API의 해외 주문 취소 결과 판정 (backend/order_outcome.py, 버전 3311fb4e82aa)  

원본 취소 처리와 화면 출력 함수에 가상 응답을 넣어 재현했습니다. NH 서버 호출과 실제 주문 전송은 없습니다.

## 재현 절차

1. NH 프로젝트 폴더 안에 아래 링크의 reproduce_R20.zip을 받아 압축을 풀고 RUN_REPRO.cmd 실행 (프로젝트 Python 환경과 Node.js 필요)
2. 원주문 80번(ZNZ26, 미체결 1계약)에 대한 취소 요청에 접수번호 100번 반환
3. 주문오류내역은 0건, 주문내역 첫 페이지는 다른 주문과 다음 페이지 키(PAGE_2)를 반환
4. 두 번째 페이지에는 원주문 80번이 잔량 1계약으로 남아 있도록 구성
5. 원주문을 첫 페이지로 옮긴 경우와, 원주문이 전체 내역에서 없어진 정상 취소도 비교

※ 2~5번은 재현 코드가 자동으로 실행합니다. 매수·매도 각각 확인합니다.

## 기대 결과

조회하지 않은 다음 페이지에 원주문이 남아 있을 수 있으므로 취소 완료로 단정하지 않아야 함. 원주문이 확인될 때까지 결과 미확인으로 표시하거나 다음 페이지를 조회해야 함.

## 실제 결과

- 원주문이 두 번째 페이지에 잔량 1계약으로 남아 있는데 outcome.state가 accepted로 나오고, 화면 출력 함수도 '취소됨'을 표시
- 다음 페이지 키가 있어도 첫 페이지만 조회하고 판정 종료
- 같은 원주문이 첫 페이지에 있으면 unknown으로 나오며 '취소 접수됨 / 결과 미확인' 표시
- 원주문이 전체 내역에서 없어진 정상 취소는 '취소됨' 표시
- 매도 주문도 같은 결과

## 근거 (재현 코드·실행 결과)

- [reproduce_R20.zip](./reproduce_R20.zip): 재현 코드, 공개 원본 소스, 실행 설명
- [result.json](./result.json): 매수·매도 6가지 사례의 요청·응답, 조회한 페이지, 화면 출력 결과

## 영향

미체결 주문이 남아 있어도 취소된 것으로 판단할 수 있어, 이후 원치 않는 체결을 놓칠 수 있음.

## 개선 제안

다음 페이지가 남아 있으면 첫 페이지에 원주문이 없다는 이유만으로 취소 완료를 확정하지 않도록 수정. 다음 페이지를 확인하지 못한 경우 결과 미확인으로 처리.
