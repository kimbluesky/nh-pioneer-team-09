기대 결과
대기 시간이 예정 시각보다 길어져도 같은 계정·시장·등급에서 연속 API 요청 시작 사이에 최소 간격이 유지되어야 합니다.
시세 등급에서 2번째 호출이 0.40초에 반환됐다면 3번째는 0.50초 이후, 주문 등급에서 2번째 호출이 0.50초에 반환됐다면 3번째는 0.70초 이후여야 합니다.

영향
OS 스케줄링이나 스레드 실행 지연 등으로 RateLimiter의 sleep()이 예상보다 늦게 끝난 뒤에는, 다음 요청을 너무 일찍 통과시킬 수 있습니다. 이 경우 애플리케이션이 의도한 초당 호출 간격이 지켜지지 않아 요청이 몰릴 가능성이 있습니다. 실제 NH API에서 제한 초과 오류가 발생하는지는 검증하지 않았습니다.

개선 제안
RateLimiter가 요청 예정 시각만 예약하는 것으로 끝내지 않고 실제 대기 종료 시각을 반영하여 다음 허용 시각을 갱신하도록 수정해 주세요. 여러 스레드에서 같은 호출 키를 사용할 때도 전송 시작 간격이 유지되도록 동기화를 보완하고, 대기 시간이 늦게 끝나는 경우를 회귀 테스트에 추가해 주세요.
