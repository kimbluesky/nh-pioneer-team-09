# [제보] NH FUTURES API: 분봉 재조회와 실시간 봉이 겹치면 동일 시각 봉이 중복되어 지표 계산이 달라집니다

팀: team-09
환경: Python 3.13.5, 오프라인 재현(NH 서버 호출 없음), 2026-11-20 KST
대상: 공개 저장소 NH FUTURES API의 전략 검증 분봉 생성·재조회 병합 
(backend/strategy/bars.py의 BarBuilder.seed/add/close, 원본 nh-futures-open-api-main.zip)

## 재현 절차
1. reproduce_R23.zip을 원하는 폴더에 넣고 아래 명령을 실행합니다. 압축을 풀거나 NH 프로젝트를 설치할 필요는 없습니다.
   py -3.12 -B reproduce_R23.zip --output R23_result.json
2. 동봉된 원본 Python 파일 6개의 SHA-256 무결성을 검사합니다.
3. 5분봉, 국내 주간 세션에서 2026-11-20 10:01 KST, 가격 100의 실시간 체결을 입력해 10:00 봉을 엽니다.
4. 이 봉이 열려 있는 동안 같은 10:00 시각의 과거 조회 분봉(종가 99)을 재조회 데이터로 넣습니다.
5. 10:05, 가격 101의 다음 실시간 체결을 입력하고 봉을 닫아 저장된 봉들의 시각과 지표를 확인합니다. 재조회하지 않는 대조군, 과거 09:55만 조회하는 대조군, 이미 닫힌 10:00 봉을 재조회하는 대조군과 비교합니다.

※ 2~5번은 스크립트가 자동 실행합니다. 모든 시세·호가는 검증용 합성 데이터이며 실제 거래소 응답이 아닙니다.

## 기대 결과
10:00~10:04는 하나의 5분 구간이므로 과거 조회 봉과 실시간 집계 봉이 겹쳐도 10:00 봉은 하나만 남아야 합니다. 두 구간(10:00, 10:05)에 대한 봉 수·지표 준비 여부가 일관되어야 합니다.

## 실제 결과
- 재조회 없는 대조군: 10:00, 10:05 봉 각각 1건(총 2건)
- 09:55 과거 봉만 재조회한 대조군: 09:55, 10:00, 10:05 봉 각각 1건(중복 없음)
- 이미 닫힌 10:00 봉을 재조회한 대조군: 10:00, 10:05 봉 각각 1건(중복 없음)
- 오류군: 10:00 종가 99(과거 조회), 10:00 종가 100(실시간 집계), 10:05 종가 101 → 전체 3봉, 실제 구간 2개, 10:00 시각 중복
- 대조군의 ready(3)은 false이고 SMA(3) 마지막 값은 None인데, 오류군은 ready(3)이 true이고 SMA(3) 마지막 값 100이 계산됩니다.
- 과거 조회 가격과 실시간 가격을 같게 하거나, 최초 차트 조회 후 실시간을 이어 받거나, 조회 직후 세션을 닫는 경우에도 중복 확인
- 결과 JSON의 bug_reproduced = true, checks 8/8 통과

## 영향
전략이 과거 분봉을 다시 받아 채우는 도중 실시간으로 생성 중인 봉과 시간대가 겹치면 같은 봉이 두 번 들어갈 수 있습니다. 이는 봉 수로 판단하는 준비 상태와 이동평균 등 지표 계산에 잘못된 입력을 제공하여 전략 검증의 조건 평가에 영향을 줄 수 있습니다. 이번 검증은 BarBuilder와 sma 실행까지만 확인했으며 실제 주문 생성까지 입증한 것은 아닙니다.

## 개선 제안
BarBuilder.seed()에서 조회 봉의 시각이 열려 있는 실시간 봉의 구간과 같으면 중복으로 닫힌 봉 목록에 삽입하지 않도록 처리해 주세요. close()에서도 동일 타임스탬프 봉이 이미 있는지 확인해 한 구간이 정확히 하나의 봉으로 유지되도록 수정해 주세요.
