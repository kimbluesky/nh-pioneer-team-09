[제보] NH FUTURES API: 전략 조건의 비교값을 숫자 0으로 전달하면 정상적인 매수·청산 신호가 발생하지 않습니다

팀: team-09
환경: Python 3.13.5, 오프라인 재현(NH 서버 호출 없음), 2026-11-23 KST
대상: 공개 저장소 NH FUTURES API 전략 조건 저장 검사·판정 (backend/strategy/validate.py, backend/strategy/rules.py)

재현 절차
1. reproduce_R24.zip을 준비된 폴더에 둔 뒤 아래 명령을 실행합니다. 압축 해제나 별도 NH 프로젝트 설치는 필요하지 않습니다.
   py -3.12 -B reproduce_R24.zip --output R24_result.json
2. ZIP에 포함된 원본 Python 파일 11개의 SHA-256 무결성을 검사합니다.
3. 국내 주간 5분봉을 기준으로 다음 조건을 설정합니다.
   - 매수 진입: 거래량 volume > 0
   - 매수 보유 청산: 평가손익 openPl < 0
4. 합성 봉 3개를 입력합니다.
   - 10:00 거래량 0, 평가손익 +5
   - 10:05 거래량 12, 평가손익 -5
   - 10:10 거래량 14, 평가손익 -7
5. 비교값 right를 JSON 숫자 0으로 전달한 경우와 문자열 "0"으로 전달한 경우를 각각 비교합니다. 0.0/"0.0", 1/"1" 대조군도 함께 실행합니다.

기대 결과
JSON 숫자 0과 문자열 "0"은 동일한 숫자 기준값을 뜻합니다. 두 형식 모두 저장 검사를 통과하므로 거래량 0→12에서 buyEntry 신호 1건, 평가손익 +5→-5에서 buyExit 신호 1건이 발생해야 합니다.

실제 결과
- 문자열 "0": 거래량 조건 매수 신호 1건(봉 2), 평가손익 조건 청산 신호 1건(봉 2)
- 숫자 0: 두 조건 모두 저장 유효성 검사를 통과하지만 신호 0건
- 숫자 0.0: 같은 문제 발생 / 문자열 "0.0": 정상 신호
- 숫자 1과 문자열 "1": 두 조건 모두 정상적으로 신호 발생
- 원본 rules.right_at()의 오른쪽 비교값: 숫자 0 → None, 문자열 "0" → 0.0
- result.json의 bug_reproduced=true, 검사 14/14 통과

영향
전략 설정을 API/JSON으로 생성·저장할 때 비교 기준을 JSON 숫자 0으로 전달하면, 유효한 전략으로 저장되더라도 거래량 진입 조건 또는 평가손익 청산 조건이 동작하지 않을 수 있습니다. 화면에서 값을 문자열로 보내는 경우에는 같은 문제가 발생하지 않습니다.

개선 제안
rules.right_at()에서 cond.get("right") or "" 표현으로 0을 빈 값으로 바꾸지 말고, None 여부를 구분하여 0/0.0을 그대로 수치 변환하도록 수정해 주세요. 전략 검증기에서 받아들이는 입력 형태와 엔진의 조건 판정이 일치하도록 숫자 0과 문자열 "0"을 모두 회귀 테스트에 포함해 주세요.
